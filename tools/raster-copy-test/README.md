# rastercopytest — ラスタコピー目視確認ディスク

CRTC のラスタコピーが「動作ポート bit 3 が 1 の間ずっと」実行されるのか、
それとも「レジスタを書いた瞬間だけ」なのかを、目で見て区別するための
セルフブート X68000 プログラムです。Human68k などの著作物は含まず、
IPLROM の IOCS(`_CRTMOD`/`_G_CLR_ON`/`_B_PRINT`)だけで動きます。

## 見かた

テキストラスタのブロック 20(上のバー)が**コピー元**で、プログラムは
ここだけを書き換えてバーを左から右へ動かします。ブロック 30(下のバー)は
**コピー先**で、R22 は起動時に一度だけ設定したあと二度と書きません。

その状態で動作ポートの bit 3 だけを数秒ごとに切り替えます。

| 表示 | 期待される挙動 |
|---|---|
| `COPY ON` | 下のバーが上のバーに**追従する**(同じレジスタ値のまま毎水平フロントポーチで再実行されるため) |
| `COPY OFF` | 下のバーが**その場で凍結**し、上のバーだけ動き続ける |

判定はこうなります。

- 下のバーが最初から一度も動かない → コピーがレジスタ書き込み時にしか
  起きていない(bit 3 をトリガーとして扱ってしまっている)
- `COPY OFF` にしても下のバーが動き続ける → bit 3 がレベルとして
  尊重されていない

bit 3 が保持型(0 を書くまで 1 のまま、各水平フロントポーチで実行、
トリガーでも完了フラグでもない)であることは、X68000 Technical Guide が
書き込み値「0=停止 / 1=実行」と読み出し「ラスタコピー動作中」を区別して
いること、Inside X68000 が自動リセットを高速クリア(bit 1)と画像入力
(bit 0)についてのみ記載していること、および XEiJ の実装が根拠です。

## レジスタの単位

R22 は 4 ラスタを 1 単位とするブロック番号で指定します。バイト `$2C` が
コピー元ブロック、`$2D` がコピー先ブロックで、実アドレスはそれぞれ
ブロック番号 × 512 バイトです。R21 の下位 4 ビットでコピー対象プレーンを
選びます。このプログラムはプレーン 0 だけをコピーするので、バーは
テキストカラー 1 で出ます。

## 使い方

`rastercopytest.xdf` を FDD0 に挿入して起動(HDD は外すかブート順を FD に)。
ROM(IPLROM/CGROM)は通常どおり必要です。

## ビルド

```bash
./build.sh
```

GNU binutils (m68k) が必要です(Debian/Ubuntu: `binutils-m68k-linux-gnu`)。
macOS では Homebrew の `m68k-elf-binutils` を入れて:

```bash
PREFIX=m68k-elf- ./build.sh
```

生成される `rastercopytest.xdf` は生の 2HD ダンプ(77シリンダ×2面×8セクタ×1KB)で、
先頭 1KB のブートセクタにプログラム全体が入っています。
